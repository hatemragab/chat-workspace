# Flutter chat client

Android and Web client using Riverpod, Drift, Dio, Centrifugo, `v_chat_bubbles`, and `v_chat_input_ui`. The source follows [FLUTTER_SPEC.md](../FLUTTER_SPEC.md); [the workspace README](../README.md) contains service setup and two-browser commands.

`lib/core/` contains typed API models, HTTP handling, SQLite storage, the inbox queue, reconciliation, session lifecycle, optimistic sends and presence. `lib/ui/` contains responsive authentication, inbox, direct/group entry, Telegram-style messages, image attachments, actions, reply jumps and diagnostics. `lib/main.dart` starts the provider scope and semantic accessibility support.

Run `flutter pub get` before development. Configure `API_BASE_URL` and `CENTRIFUGO_URL` using `--dart-define`. All builds default to localhost. For physical-device debug builds, supply the development machine’s reachable LAN address with `--dart-define=LOCAL_WIFI_HOST=192.168.1.10` (illustrative address), or override both URL defines. The shared defaults are in `lib/core/network_config.dart`. Build the connected-device APK with `flutter build apk --debug --dart-define=LOCAL_WIFI_HOST=192.168.1.10`, replacing the example host, while the phone and development machine share Wi-Fi. The API must run in development mode (or with `HOST=0.0.0.0`), and Centrifugo must use the LAN listener configured below. Separate localhost ports 5173 and 5174 provide independent account storage for web verification. For an Android environment reaching the host through its loopback bridge, build with `http://10.0.2.2:3000` and `ws://10.0.2.2:8000/connection/websocket`; use the appropriate reachable host for a physical device. The Android project uses compile SDK 37 and AGP 9.1.1. Local cleartext connections are enabled only in debug/profile manifests.

The Drift tables are `SyncMetadata`, `LocalRooms`, `LocalMessages` and `ReceiptTasks` in the single `chat_app_db`. Current schema version 6 upgrades versions 1–5 without clearing rows or the inbox cursor. Version 5 adds message sequences, cumulative receipt state and durable acknowledgement tasks; the compact unread follow-up needs no additional migration. Version 4 added an account/epoch-scoped authoritative room page cursor, an indexed reply target and bounded pending upload bytes. Version 3 message certification remains valid. Version 1 also replaces its UUID-only constraint with `(senderId, idempotencyKey)` uniqueness. Both old versions invalidate only `messagesSyncedPts` once, so normal room opening repairs previously stale receipts/quotes; subsequent launches reuse newly verified baselines. Explicit logout and changing accounts clear account data and fence stale asynchronous operations, including draft remapping and delete-for-me continuations. Interrupted sends return to the persistent sequential queue on startup with their original identity and an unknown server outcome. New sends recover automatically when the API returns; permanently invalid requests remain failed until explicit Retry. `web/sqlite3.wasm` and `web/drift_worker.js` are required runtime assets. Regenerate database bindings only after an intentional table/schema change using `dart run build_runner build --delete-conflicting-outputs`.

Compact `receipt` events update peer ticks; compact `unread` events apply the exact remaining unread count and own acknowledgement cursors without changing outgoing ticks, previews, content revisions or message certification. Both commit through the serialized inbox queue with its cursor. Hydrated REST/Redis snapshots recover missed events, including unread state coalesced into later preferences. Enable backend `RECEIPT_PUSH_MODE=compact` only after all clients support both compact envelopes; legacy hydrated events remain accepted. See [receipt validation](../RECEIPT_SEQUENCE_VALIDATION.md) for offline SQLite and live browser evidence.

Saved sessions and cached conversations open from Drift before HTTP completes. Sent, sending and failed messages remain visible while the API is unavailable, and cached history, reply targets and Return to Latest work locally. Text sends enter Drift immediately and drain in strict global FIFO order. Temporary outages pause and recover automatically; permanent validation failures remain visible without an automatic loop. A first pending draft send also persists a local inbox entry, so failed first messages remain reachable after restart; acknowledgement remaps its messages and removes the draft entry atomically. Inbox/latest-page reconciliation runs in the background and retries on recovery; displaying cached rows does not advance the inbox cursor or certify their freshness. New sign-in, uncached history, upload transfer and server mutations still require the server. Selected images are first persisted locally with their original send identity, filename and bytes, including every item of a batch before its first upload. Failed uploads and interrupted sends can be retried after restart; a successful upload removes its local blob before the message send, so a failed send does not upload again. Media URLs alone do not guarantee persistent offline image bytes, and this change does not add a Web app-shell service worker for a fully disconnected browser reload.

The composer captures its initiating account and conversation before recovery or upload awaits, including an entire multi-image batch. Later optimistic batch items resolve the original draft to its known real room, keeping sending/failed images visible and retryable even after the first acknowledgement. Its identity follows the direct peer across lazy draft creation, preserving the next unsent draft and focus. Connection/upload banners preserve that composer, and its separate accessibility group keeps the Web text field stable when Send appears. Account, session and conversation changes clear that input. The reversed viewport fills the chat area and anchors short conversations at the bottom. Historical jumps revalidate after missed edits/deletions; safe quote-only events update visible quotes without inserting hidden originals. Latest direct pages recover receipt ticks across older cached rows; gapped or legacy responses reset older sent history while preserving pending/failed sends. Optional debug-account discovery cannot block saved-session recovery and can be retried.

Logout immediately fences the outgoing session, including during unfinished startup. It cancels status refreshes and calls `/presence/offline` with the old credentials before clearing them. That best-effort request has a three-second bound; an unresponsive startup HTTP request cannot hold release or local cleanup open. Retired requests cannot affect a later account. Foreground sessions refresh statuses only for unique peers in loaded, non-deleted direct-chat rooms, excluding local drafts and directory-only users. No status request is sent when there are no eligible peers. Refreshes run every 30 seconds (`PRESENCE_REFRESH_SECONDS`), on reconnect/resume/startup/manual sync, without application heartbeats. Centrifugo's current inbox connections determine online status, including background sockets that remain open. Other connected logins keep the account online. Legacy presence hints remain accepted as snapshot invalidations but are no longer emitted by the backend.

Open **Sync diagnostics**, scroll to **SQLite database rows**, and expand it to inspect a read-only local snapshot. Authentication tokens are excluded. The panel also shows revision counters, connection status, request counts and recent operational events. Keep copied diagnostics private because local room/message content may be included in the row snapshot.

Debug builds record API completion metadata including timestamp, the initiating session's user ID, method, route template, status, duration and response `X-Request-ID`. Identity is captured when the request starts, so a later account switch cannot misattribute its completion. OPTIONS are excluded. Debug app launches enable **Full debug traffic logging** automatically to include full request/response JSON, route parameters, queries and received realtime publication data. Authentication credentials are recursively redacted and binary uploads use file metadata. Release builds cannot enable this logger.

Full records share `event`, `source`, UTC `timestamp` and `userId` fields across HTTP and realtime. A received publication records its receiving `recipientUserId` and channel; the client does not invent an actor or request ID absent from the wire payload. The backend records the validated actor, recipient and causative request ID for publish attempts. Match HTTP response request IDs with those backend records. The diagnostic panel retains the latest 60 full traffic entries, with HTTP/realtime counts grouped by user for that retained window; turning the switch off clears those full entries and prevents recording in-flight payloads afterward. Metadata-only HTTP history remains separately bounded.

Run the backend with `npm run start:dev` (logging enabled by default) from `backend/`. Backend and client full-traffic switches are independent. The separate [local Vector pipeline](../LOCAL_OBSERVABILITY.md) accepts inspector metadata and opt-in redacted HTTP/realtime/SQLite details from debug Flutter builds. Expand an HTTP completion row’s `data.http` for `params`, `query`, `requestBody`, `requestHeaders`, `responseBody` and `responseHeaders`. Realtime `socket.send.*` / `socket.receive.*` rows expose decoded protocol JSON under `data.realtime.payload`; match protocol IDs within their connection. Chat sends remain REST mutations. [Server filters](../backend/README.md#request-logs-and-correlation) are documented in the backend runbook.

## Flutter inspector

For AI/Logdy access, start the local Vector collector, then launch the debug app; **Capture** and **Share with local logs** start enabled in this inspector. It streams new structured events to `127.0.0.1:8083/events` with bounded batching and visible delivery/drop counters. **Refresh counters** exports current gauges/build/frame/operation metrics. Sharing starts on and is unavailable outside debug builds. See [local observability](../LOCAL_OBSERVABILITY.md) for each service, MCP queries, local boundaries and native-device forwarding limits.

In debug builds, open **Workspace menu → Flutter inspector** (also available in Sync diagnostics), and reproduce an issue. The bounded timeline links operations, network/realtime, inbox jobs, Drift, state notifications and principal screen builds; it also exposes query timings, active resources, widget counts and copyable JSON. Capture starts on and is unavailable in profile/release builds. Full traffic can start off with `--dart-define=DEBUG_TRAFFIC_LOGGING_ENABLED=false`; all controls remain available at runtime. See [Flutter debugging](../FLUTTER_DEBUGGING.md) for details and the separate heap/performance profiling workflow.

The Flutter inspector follow-up passed **221 tests**, formatting, analysis, the release Web build and the debug Android APK build. This includes 43 added inspector/Drift/queue/controller/widget regressions. See the latest section of [VALIDATION.md](../VALIDATION.md) for actual browser evidence and profiling limits.

Centrifugo now uses the [secured local proxy configuration](../centrifugo/README.md). Flutter passes fresh signed connection data via `getData` on reconnect, listens to client-level server subscription/publication streams, and uses the access session's actual expiry without periodic server refresh requests. It never requests an inbox subscription or Centrifugo history/recovery. New shared-room memberships refresh permitted presence snapshots. The existing serialized inbox reconciliation runs after every server subscription/reconnect.

## Recovery, storage and media policies

Only one active tab may own this origin's `chat_app_db`. Startup acquires an exclusive browser Web Lock before creating the controller/database. A second tab, an unsupported browser or a denied lock displays a storage-coordination notice and Retry; close the first tab to transfer ownership. Closing, reloading or crashing releases the browser lock. The two development origins on ports 5173/5174 remain independent.

An expired or revoked running session pauses remote recovery and displays **Sign in again**. Cached history, failed messages and pending image bytes remain local. Signing into the same account preserves them; explicit logout or choosing another account performs the normal fenced cleanup. Infrastructure errors such as HTTP 503 do not invalidate the session. Presence snapshot failure has a separate degraded-status notice and does not label working messaging offline. Unchanged snapshots do not trigger controller notifications. Only a visible, resumed conversation sends Seen; background clients still acknowledge delivery.

The server's unpinned `nextCursor` is stored atomically with full-inbox reconciliation and after successful page loads. Deltas and pin changes never move it. A missing or old-epoch boundary bootstraps the first server page; pinned full-sync pages are fetched in batches of 100 before inbox certification. People discovery uses 100-user pages with **Load more people**. Demo login controls are available only in debug builds.

All image/avatar/quote reads use bearer-authenticated Dio byte requests. Tokens never enter image URLs or query strings. The session-scoped in-memory cache is bounded to 64 images / 20 MiB and is cleared on credential changes. Pending uploads are limited to 5 MiB each, 20 files and 20 MiB combined, with one upload in flight per session. Byte persistence depends on browser/device storage availability; a quota write failure is shown and never certifies an unsaved task. The database row inspector shows blob length instead of blob content. There is no automatic deletion of server media or local pending work.

Room bootstrap reads at most 51 messages; ordinary windows start at 50 and expand by 30 through bounded queries. The viewport uses a lazy sliver list. A cached reply jump reads a local 31-message context with Return to Latest rather than loading its entire history. Contiguous publications batch at most 64 events into one transaction, preserving every content/receipt/quote update and advancing the cursor only with those writes. Gaps and epoch changes retain serialized REST recovery. Inspector gauges report completed batch/event counts, and queue-start records include waiting duration separately from operation execution. Recognized Drift cancellation is a cancelled outcome rather than a database error.

Direct-chat headers and the people picker consume the authorized `/presence/status` snapshot: connected peers show **Online**, offline peers show **Last seen <date> at <time>** in device-local time and its 12/24-hour format. Missing or invalid timestamps fall back to **Offline** for a confirmed offline peer; unknown/unauthorized peers retain the conversation hint. Snapshot failures preserve the previous state. Last-seen values remain session-scoped in memory and clear on logout/account switch; no database migration or extra refresh timer is introduced.

## Sequential send queue

See [outbox and health recovery](../OUTBOX_QUEUE_AND_HEALTH_SPEC.md) for durable states, strict global FIFO, retry budgets, authentication, uploaded-image checkpoints and diagnostics. Sync diagnostics exposes the outbox state and counters. Enable Flutter inspector Capture and Share with local logs to follow `outbox` and `health` categories in [Logdy](http://127.0.0.1:8082/).

## Selected policies

- Preserve the approved REST/MongoDB/Redis/Centrifugo/single-Drift/serialized-cursor architecture.
- Foreground visible conversations produce Seen; background receipt and delivery remain separate.
- One active app writer per browser origin; a duplicate tab is visibly blocked until ownership is available. Ports 5173 and 5174 remain independent.
- Infrastructure outages are retryable and preserve sessions/offline work. Actual expired/revoked sessions require reauthentication without silently erasing pending work; explicit account changes retain cleanup fences.
- Image reads require authentication and current authorization; global deletion revokes subsequent server reads. Previously downloaded bytes cannot be recalled. Legacy image URLs remain recognizable and require visible-message authorization.
- Persist bounded interrupted image-upload tasks, account/conversation identity and retry identity.
- Media cleanup is dry-run by default; no existing media/data deletion is part of the authorized logs-only clear.
- Full application payload capture is development-only unless a conspicuous explicit operational override is configured; metadata capture remains independent.
- Logging is bounded and exposes omission/loss/lag. No design promises unbounded or lossless capture.
